What Forth is

  • A stack. Values go on it and come off it.
  • A dictionary. A list of named things.
  • Words. Each name is one, and you add your own.

That is the whole language.

Chuck Moore wrote the first Forth in the late 1960s, to point radio telescopes. It went on to run boot firmware: Sun's OpenBoot and Apple's Open Firmware were both Forth, and so was the FreeBSD boot loader. The reason we can read a whole Forth aloud in one talk is this slide. There is no type system, no syntax to speak of, no separate compiler. Three ideas, and the rest is built out of them.

Reverse Polish

The operator comes after its arguments.

infix(3 + 4) * 5
Forth3 4 + 5 *

No precedence. No parentheses. Left to right, always.

If you have used an HP calculator, you already know this. Ask the room. Note what is missing on the Forth line: there are no brackets, and there is no rule to remember about times binding tighter than plus. The order you write things in is the order they happen in. That is not a simplification for the slide - it is the whole parsing story.

The stack

One stack of 64-bit cells. Everything travels on it.

1
2
3
1 2 3

Arguments come off it. Results go back on it.

Press once per cell. Typing "1 2 3" leaves three cells, three on top. A cell is 64 bits and holds anything: a number, a character, an address. Forth does not track which. That is the trade - the language gets very small, and the discipline about what is on the stack is yours. There is a second stack. We will get to it once we have something that needs it.

Words and the dictionary

A word is a name with some code behind it.

The dictionary is a list of them, newest first.

Typing a name runs that word. That is all typing does.

There is no keyword list. DUP is not built into a parser - it is an entry in the dictionary, exactly like a word you write yourself. Newest first matters: if you define a word that already exists, yours is found first and the old one is still there underneath. WORDS prints the dictionary. In the next talk you will see the list grow as we add to it.

What typing a line does

  1. Cut off the next word at a space.
  2. Look it up in the dictionary. Found? Run it.
  3. Not found? Read it as a number and push it.
  4. Neither? Complain.
  5. Line empty? Print ok and read another.
This loop is the whole of what people call the outer interpreter, and in the next talk it is about a page of assembly. Note the order. A word wins over a number. Nothing is reserved, so there is nothing stopping you defining a word called 42 - and then 42 means your word. The complaint is the word back at you with a question mark: type FOO and you get "FOO ?". A space is the only separator. That is why every Forth word is written with spaces around it, including the ones that look like punctuation.

Defining a word


: SQUARE  DUP * ;
  • : starts a definition and takes the next word as its name.
  • What follows is the body.
  • ; ends it.

Now SQUARE is a word like any other.

Read it aloud: colon, SQUARE, DUP, times, semicolon. DUP makes a second copy of the argument, times multiplies the two. No parameter list, no return statement - the stack is both. And say the important part: the colon and the semicolon are themselves words in the dictionary. We will come back to that.

Let us define one


: SQUARE ( n -- n*n ) DUP * ;
 ok
7 SQUARE .
49  ok

Stack-effect comments


: SQUARE  ( n -- n*n )      DUP * ;
: CUBE    ( n -- n*n*n )    DUP SQUARE * ;
: NIP     ( n1 n2 -- n2 )   SWAP DROP ;

Before the --, what it takes. After, what it leaves.

Not syntax: ( is a word that skips to the ), and \ is a word that skips the rest of the line.

This is the closest thing Forth has to a type signature, and it is entirely a convention - a comment. Every word in the repo we are about to read carries one, and they are how you follow the code without running it. Read the NIP one out: takes two items, leaves the second. Which is what SWAP DROP does. CUBE is the one to linger on: it is a word built out of a word you wrote a slide ago. DUP leaves two copies, SQUARE turns the top one into n squared, and the multiply finishes it. The next slide needs a word that calls a word, and this is it. The second point is the one to land. The open bracket is a word in the dictionary. It runs, and what it does is move the input position past the closing bracket. Forth has no syntax for comments because Forth has almost no syntax.

Two stacks

1
3
2
data stack: values
in CUBE
in SQUARE
return stack: where to come back to
Now that a word can call a word, the second stack has a job. When CUBE calls SQUARE, something has to remember where in CUBE to carry on. That is the return stack. Every other language has this too - it is the call stack - the difference is that in Forth it is a separate stack from the one your values are on. And that is exactly why it is separate. If arguments and return addresses shared a stack, a word could not leave its results just sitting there for the caller to pick up.

You can use it too

>Rmove the top item to the return stack
R>move it back
R@copy it back, leaving it there

What you take, you put back before the word ends.

Useful when you need to get something out of the way: park it on the return stack, work on what is underneath, bring it back. The rule on the slide is not advice. The return stack is holding the address the word returns to. Leave something extra on it and the word returns to your number instead. Nothing checks, and the crash is not near the mistake. In the next talk you will see these three words implemented, and they are three instructions each.

Most of Forth is written in Forth


: NIP     ( n1 n2 -- n2 )       SWAP DROP ;          \ drop the one underneath
: TUCK    ( n1 n2 -- n2 n1 n2 ) SWAP OVER ;          \ a copy of n2 below n1
: NEGATE  ( n -- -n )           0 SWAP - ;           \ 0 - n is -n
: ABS     ( n -- |n| )          DUP 0< IF NEGATE THEN ;

Straight out of lib/prelude.f. Nothing special about them.

These are four real lines from the Forth we are about to read, copied without changes. Point at ABS: it calls NEGATE, which is defined two lines above it. The file is ordered so that every word uses only words already defined. This is the claim Forth makes about itself. You write a small core in assembly - in our case about thirty words - and everything else is ordinary definitions typed in the same language a user types.

The whole of the rest

0=0 = NIP SWAP DROP
0<0 < TUCK SWAP OVER
1+1 + ?DUP DUP IF DUP THEN
1-1 - NEGATE 0 SWAP -
2*2 * ABS DUP 0< IF NEGATE THEN
//MOD NIP MOD /MOD DROP

Thirteen words. Every body is one line.

The point of showing all of them at once is the shape, not the detail. Look at the right-hand column: every one is a line of words that already exist. None of them needed a new feature in the language. And notice what is not in the assembly core because of this. We implement /MOD, which leaves both answers, and then "/" and MOD are one line each on top of it.

Two modes

interpretingrun each word as it is read
compilingwrite each word into the definition instead

: switches to compiling. ; switches back.

It is one cell in memory holding 0 or -1.

Until now every word ran the moment it was read. Inside a colon definition that cannot happen - typing ": SQUARE DUP * ;" must not duplicate anything yet. So the interpreter has a mode, and the mode is a single cell called state. Colon sets it, semicolon clears it. That is the entire compiler's worth of bookkeeping. This also explains why a definition can span several lines: the cell outlives the line.

Except for immediate words

A word can be marked to run while the compiler is compiling.

The compiler checks that mark on every word it reads.

IF, ELSE, THEN, ; and ( are all marked.

One exception to the mode, and it is what makes the rest possible. Semicolon has to be immediate - if it were compiled like everything else, a definition could never end. And once you have that mechanism, control flow falls out of it for free. That is the next slide.

Conditions and loops


: ABS      ( n -- |n| )  DUP 0< IF NEGATE THEN ;
: SIGN     ( n -- )      0< IF ." negative" ELSE ." not negative" THEN ;
    

: COUNTDOWN ( n -- )  BEGIN DUP . 1- DUP 0= UNTIL DROP CR ;
: STARS     ( n -- )  0 DO 42 EMIT LOOP CR ;
IF takes a flag off the stack. Not-zero runs the part up to ELSE, zero runs the part after it. Worth pointing at the difference between the two lines: 0< eats the number it tests. ABS still wants that number afterwards, so it DUPs it first. SIGN only prints, so it does not, and it leaves the stack as it found it. THEN is not "then" in the English sense - it means "at this point", the place both paths meet. Everyone reads it wrong once. Forth's false is 0 and its true is -1, every bit set, which is why the same AND and OR serve for bits and for logic. The loops go on the second half of the slide and we are not dwelling on them. BEGIN UNTIL tests at the bottom; DO LOOP counts, and I is the counter. Both definitions run: "5 COUNTDOWN" prints 5 4 3 2 1 and "7 STARS" prints seven asterisks.

IF is not syntax


: IF                    ( -- hole )
    ['] 0BRANCH ,       \ compile the jump: 0BRANCH takes it when the flag is 0
    HERE                \ where the cell holding that jump's target goes
    0 ,                 \ lay it down empty - nobody knows the target yet
;                       \ and leave its address for THEN or ELSE to fill in
IMMEDIATE
[']the execution token of the word named after it
,lay one cell down at HERE
HEREthe address the next cell will go to

A word, in the dictionary, written in Forth.

This is the slide the whole deck exists for. Copied unchanged from lib/prelude.f. Walk the lines. IF is an immediate word, so when the compiler meets it inside a definition it runs it. What it does is write a conditional jump into the word being defined, then write an empty cell after it, because at this moment nobody knows where the jump goes. It leaves the address of that empty cell on the stack. THEN, later in the line, is another immediate word. It takes that address and fills in where we have got to. So a conditional is compiled by two ordinary words passing an address between them on the data stack. Nothing in the parser knows what IF means. If you do not like it, you can write your own.

What you now know

  • Arguments on a stack, operator last.
  • A word is a name in a dictionary.
  • : and ; define one.
  • A second stack holds where to come back to.
  • Control flow is words, not syntax.
Five things. If the room has these, the next talk works. Nothing here was about how any of it is implemented, which is deliberate - that is the whole of the next talk, and it is about two thousand lines of assembly.
